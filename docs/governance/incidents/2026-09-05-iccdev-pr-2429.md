# Incident: Review-Driven MCP Discovery Repair on iccDEV PR #2429

Date: 2026-09-05

## Summary

An MCP SDK migration was pushed after focused local tests passed, but the
subprocess regression did not prove its no-install import path or Windows pipe
behavior. Cloud review then became the discovery mechanism for those omissions.

## Impact

- Two cloud review cycles found defects in a three-file fix.
- The first repair was published before a complete cumulative audit.
- The second review found cleanup and suppressed documentation defects.
- A local automated review was launched after the second-review stop condition.

## Root Causes

1. Editable-install test success was treated as evidence for a child process
   launched from an uninstalled source tree.
2. The complete platform and installation-mode matrix was not reviewed before
   the first push.
3. Active and suppressed findings were not inventoried as one closure input.
4. The review-stop rule was documented but not used as an operational gate.

## Corrective Actions

- Require a local cumulative review before cloud review.
- Require package, protocol, and subprocess changes to record supported
  platform and installation-mode results, including source-tree child imports.
- Require per-cycle active and suppressed finding inventories tied to exact
  head SHAs.
- After a new blocker in cloud re-review, prohibit another local or cloud
  review, repair publication, or readiness claim without maintainer direction.

## Decision

Cloud review is final verification, not iterative defect discovery. A second
cloud-review blocker sets `review-stop: FAIL - maintainer direction required`.
