# Incident: iccDEV Stack #2362/#2363 Preparedness Failure

Date: 2026-09-02

## Summary

The `ci-qa-iccconnect-threading` and `ci-qa-perf-analysis` stack was opened
before its complete cumulative diff, cross-platform fixture contract, and
CodeQL query behavior had one recorded readiness decision. Review feedback
then became an implementation loop, expanding the branch beyond its C++ focus
and producing 20 Copilot review submissions on the child PR.

The original scope was the C++ threading and bounded profiling implementation.
Later QA, workflow, CTest, CodeQL policy, lockfile, and query changes obscured
that focus and introduced independent failure modes. The stack continued to
receive individual repair commits after the second new-blocker review, despite
the documented stop rule. Resolving all active threads was treated as closure
even though it established only thread administration, not cumulative-diff
readiness.

There was no recorded final audit covering the exact child head before the
repeated repair pushes.

## What Went Wrong

1. The pre-PR Cloud Agent review was requested but not completed before the
   branches were pushed and later opened.
2. The PR scope expanded from C++ implementation to QA, workflow, CTest, and
   CodeQL policy work without a new scope decision or separate branch.
3. A policy reduction removed five CodeQL rules from the default suite. It was
   later reversed after review identified that it was unrelated to the stated
   feature.
4. A Linux-valid MCS CTest used source-tree profile paths, but Windows produces
   those profiles in the disposable `windows-testing` fixture tree. CI, rather
   than the platform contract review, found the mismatch.
5. The custom loop query accepted equality-only and unrelated `min()` compound
   conditions as bounds. Suppressed review feedback identified the resulting
   false negatives after multiple review passes.
6. Docker CI initially assumed a stacked parent SHA had a published GHCR image.
   An unmerged stack parent did not, so the job failed before its intended
   verification path.
7. A diagnostics repair reported a literal zero for asynchronous work rather
   than the actual queued worker-strip count. Its correction, trace hardening,
   and timing-precision changes were published as separate follow-up commits
   instead of as one reviewed diagnostics contract.
8. The child PR description initially named only two issues. It did not state
   acceptance criteria for the CodeQL query and pack changes, trusted
   sanitizer boundary, or deliberate retirement of the brittle Docker PR lane.
   The description was expanded only after review identified the omission.
9. After the second new-blocker review, each additional review finding was
   addressed with another push. This violated the stop rule and converted
   external review into the primary discovery mechanism.

The core `CIccApplyThreadedCmm` threading layer was not identified as defective.
The later command-line timing diagnostic was defective and required a separate
repair. The process failure was publishing unrelated, incompletely mapped
supporting changes in the same PR, treating serial review as the discovery
mechanism, and allowing a zero-unresolved-thread state to stand in for a
complete readiness decision.

## Corrective Requirements

1. After a second review identifies a new blocker, stop all repair pushes to
   that PR branch. A branch-only audit must produce a new exact-head evidence
   record before any further publication or review is considered.
2. Before the first push intended for review, write
   `.github/checklists/upstream-pr-review-evidence.md` with the exact local
   review count, complete changed surface, and required platform map.
3. Keep C++ feature implementation, CodeQL policy changes, workflow changes,
   and CTest infrastructure changes in separate commits and normally separate
   PR layers. A review finding cannot be used to add adjacent improvements.
4. For every generated fixture, record the producer and consumer path on each
   supported platform before running any test. A Unix source-tree path is not
   evidence for a Windows disposable fixture path.
5. Treat a Cloud Agent review as a final cumulative-diff gate. Do not request a
   follow-up review until every active and suppressed finding has a documented
   local disposition and the same complete matrix is green.
6. A resolved review thread is not readiness evidence. The closure record must
   bind the full PR description, complete `base...HEAD` diff, review inventory,
   configuration-contract matrix, and local results to one exact commit SHA.
7. Record a decision before changing a CodeQL default suite. Query-signal work
   needs its own rationale, positive and negative query tests, and review
   scope.
8. State intentional policy decisions, including CI-lane retirement, in the PR
   description before review. A reviewer request that conflicts with such a
   decision requires an explicit disposition, not a compensating implementation
   change.
