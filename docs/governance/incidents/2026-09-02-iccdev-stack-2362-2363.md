# Incident: iccDEV Stack #2362/#2363 Preparedness Failure

Date: 2026-09-02

## Summary

The `ci-qa-iccconnect-threading` and `ci-qa-perf-analysis` stack was opened
before its complete cumulative diff, cross-platform fixture contract, and
CodeQL query behavior had one recorded readiness decision. Review feedback
then became an implementation loop, expanding the branch beyond its C++ focus
and requiring repeated CI and Cloud Agent passes.

The original scope was the C++ threading and bounded profiling implementation.
Later QA, workflow, CTest, CodeQL policy, lockfile, and query changes obscured
that focus and introduced independent failure modes.

Four local pre-PR code reviews were documented. Their evidence did not prevent
later scope expansion because the cumulative release decision did not freeze the
reviewed file set or require a final cross-platform producer-consumer matrix.

## What Went Wrong

1. The pre-PR Cloud Agent review was requested but not completed before the
   branches were pushed and later opened.
2. The PR scope expanded from C++ implementation to QA, workflow, CTest, and
   CodeQL policy work without a new scope decision or separate branch.
3. A policy reduction removed five CodeQL rules from the default suite. It was
   later reversed after review identified that it was unrelated to the stated
   feature.
4. A Linux-valid MCS CTest used source-tree profile paths, but Windows produces
   those profiles in the disposable `windows-testing` fixture tree. CI, rather
   than the platform contract review, found the mismatch.
5. The custom loop query accepted equality-only and unrelated `min()` compound
   conditions as bounds. Suppressed review feedback identified the resulting
   false negatives after multiple review passes.
6. Docker CI initially assumed a stacked parent SHA had a published GHCR image.
   An unmerged stack parent did not, so the job failed before its intended
   verification path.

The failure was not that the core C++ commits were shown wrong. No Cloud review
finding identified a defect in the `.h` or `.cpp` threading implementation.
The failure was publishing unrelated, incompletely mapped supporting changes in
the same PR and treating serial review as the discovery mechanism.

## Corrective Requirements

1. Before the first push intended for review, write
   `.github/checklists/upstream-pr-review-evidence.md` with the exact local
   review count, complete changed surface, and required platform map.
2. Keep C++ feature implementation, CodeQL policy changes, workflow changes,
   and CTest infrastructure changes in separate commits and normally separate
   PR layers. A review finding cannot be used to add adjacent improvements.
3. For every generated fixture, record the producer and consumer path on each
   supported platform before running any test. A Unix source-tree path is not
   evidence for a Windows disposable fixture path.
4. Treat a Cloud Agent review as a final cumulative-diff gate. Do not request a
   follow-up review until every active and suppressed finding has a documented
   local disposition and the same complete matrix is green.
5. If a second Cloud Agent review identifies a new blocker, stop review
   requests. Return to branch-only grooming and conduct a complete scope,
   contract, and platform-parity audit.
6. Record a decision before changing a CodeQL default suite. Query-signal work
   needs its own rationale, positive and negative query tests, and review
   scope.
