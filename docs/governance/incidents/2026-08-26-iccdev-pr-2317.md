# Incident: iccDEV PR #2317 Pre-Review Gaps

Date: 2026-08-26

## Summary

One local pre-PR readiness review preceded the user's manual opening of PR
#2317. Three Cloud Agent review passes then occurred: the first identified four
defects, the second identified four more findings, and the third reported a
suppressed CMake-default finding. The cycle exposed gaps in the initial review
method, despite the later local preflight and build validation.

## Review-Cycle Accounting

| Review type | Count | Evidence |
| --- | ---: | --- |
| Local pre-PR readiness review | 1 | Branch-only grooming before the user opened PR #2317 |
| Cloud Agent review | 3 | #5030083527, #5030213826, #5030462939 |

The third pass carried its finding only in the review summary's suppressed
comments section, not as a resolvable review thread.

## Findings

1. Moving `iccdev-ci` user creation removed `--create-home` while retaining
   `--home-dir /workspace`; later `git config --global` requires that writable
   home directory.
2. The CTest environment unconditionally appended a runtime UBSan suppression
   path, including configurations where the file or path syntax was invalid.
3. Docker build logging checked only the Docker exit status, so a failed `tee`
   could leave a missing diagnostic log while reporting a successful build.
4. The Docker build failure summary sourced a sanitizer copied into
   `$RUNNER_TEMP` by the prior build step. A failure before that copy could
   obscure the original build failure.
5. The CMake ignorelist default was applied before compiler-specific handling,
   leaving GCC configurations warning-dirty even when no user override was
   requested.

## Gaps

1. The local review checked outcomes but did not create a per-surface contract
   matrix for defaults, explicit overrides, and failure paths.
2. Existing known-good workflow and Docker patterns were not used as mandatory
   comparison fixtures before the first review.
3. The review inventory relied too heavily on resolvable threads; suppressed
   comments in review summaries were not a first-class closure input.
4. A reviewer-proposed sanitizer name was initially treated as equivalent
   across compile-time and runtime interfaces without proving the runtime
   handler vocabulary.

## Corrective Actions

- Treat Docker user, home, ownership, and runtime global-config behavior as one
  invariant; validate it in the final image.
- Build CTest sanitizer options conditionally for supported platforms and only
  when the suppression file exists.
- Treat every command in a diagnostic pipeline as required and check all
  pipeline statuses.
- Require each failure-summary step to use a checked-in sanitizer available in
  that step or its own inline fallback.
- Require and record local preflight before the first PR create, update, or
  review request for workflow, Dockerfile, and CI-summary changes.
- Require a configuration-contract matrix and a review inventory that includes
  review summaries as well as threads.
- Treat known-good local patterns as comparison fixtures and verify reviewer
  suggestions against actual tool and runtime behavior before applying them.

## Decision

Automated review is a final gate, not the first check for Docker runtime
invariants, failure-path dependencies, diagnostic pipelines, configuration
defaults, or repository preflight compliance.
