# Incident: iccDEV PR #2327 Fixture-Contract Gaps

Date: 2026-08-26

## Summary

PR #2327 required the ten BT.2100 HDR profiles generated by the hybrid
pipeline to be represented in `Testing/qa-profile-manifest.tsv`. A local CTest
run initially exposed the manifest failure after the hybrid pipeline had
generated those profiles.

The first repair excluded `Testing/HDR/*.icc` from the manifest sweep. That
made the immediate CTest failure pass, but contradicted the PR requirement by
removing the BT.2100 profiles from coverage. A Cloud Agent review identified
the contradiction. The next repair added the Unix generator and manifest rows,
but omitted `Testing/CreateAllProfiles.bat`; a second review identified that
platform-parity gap.

## Impact

- Two review findings identified omissions that the local readiness review
  should have found before either branch update.
- The PR accumulated corrective commits instead of receiving one complete,
  review-ready fixture contract.
- Reviewer and maintainer time was spent identifying requirement and
  cross-platform gaps rather than independently confirming a finished change.

## Root Causes

1. The initial repair optimized for the failing assertion instead of the PR
   title and acceptance criterion.
2. The local scope review did not map the fixture producer-consumer chain:
   platform generators, generated HDR profiles, manifest rows, and CTest
   fixture dependencies.
3. The Unix and Windows aggregate generators were not treated as a required
   pair before the first push.
4. Cloud Agent review was used to discover omitted requirements, rather than
   as final confirmation of locally complete work.

## Corrective Actions

- Require a pre-push intent-and-parity review for every upstream PR branch.
- For fixture work, map every platform generator, generated artifact, baseline,
  and CTest dependency before editing.
- Run the smallest local test selection that proves that full map, including
  generated data and both platform implementations where applicable.
- Escalate to a full CTest run only when the mapped contract or its dependencies
  require it; unrelated coverage is not a substitute for a complete local map.
- When an automated review finds an omission, return to branch-only grooming
  and repeat the full local scope review before a follow-up push.
- Update the readiness policy, skill, prompt, and read-only readiness agent to
  record this evidence explicitly.

## Decision

Cloud Agent review and CI are final verification gates. They must not be used
to discover acceptance criteria, platform counterparts, or fixture-contract
edges that a complete local readiness review can establish before publication.
