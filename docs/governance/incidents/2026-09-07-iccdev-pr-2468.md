# Incident: Review-Service Churn on iccDEV PR #2468

Date: 2026-09-07

## Summary

`InternationalColorConsortium/iccDEV` PR #2468 added an iOS/iPadOS
`iccApplyPreview` proof-of-concept app, but the branch was not locally groomed
to a clean review-ready state before cloud review became the discovery path.
The result was repeated paid review churn: seven Copilot PR reviews, repeated
repair commits, and multiple findings that later review summaries explicitly
described as previously missed unchanged-code issues.

The primary failure was not one bad suggestion. The primary failure was that
the agent did not complete a cumulative `origin/master..HEAD` branch audit
covering app code, Objective-C++ ownership, CMake/Xcode configuration,
simulator/device launch behavior, workflows, documentation, generated assets,
and PR metadata before requesting or relying on repeated review passes.

## Impact

- Seven cloud Copilot PR reviews were posted on one PR.
- At least one local code-review task is visible in session telemetry for this
  PR; the user also reported running `/review` multiple times.
- The branch ended with fourteen commits after `origin/master`.
- Eight commits were review repair or late audit commits after the core feature
  and user-requested helper work.
- Later reviews continued to report only partial file coverage after the PR
  reached twenty-eight changed files.
- Three reviews explicitly included `Previously missed` findings in code that
  had not changed since the prior review.
- Maintainer time and paid AIC were consumed by serial review-driven discovery
  instead of one complete local grooming pass.

## Structural Review-Service Defect

The review sequence shows a service-level convergence problem:

```text
Review 1: 10/25 files reviewed
Review 2: 11/26 files reviewed
Review 3: 13/28 files reviewed, Previously missed
Review 4: 13/28 files reviewed
Review 5: 13/28 files reviewed
Review 6: 13/28 files reviewed, Previously missed
Review 7: 13/28 files reviewed, Previously missed
```

The service repeatedly reviewed only part of the PR surface, then later charged
additional review cycles to report findings that were already present in code
from earlier reviewed states. A review with this coverage profile must not be
treated as a cumulative convergence signal.

## What Went Wrong

1. The branch was pushed and reviewed before a complete local `base...HEAD`
   contract audit had been recorded.
2. The agent reacted to review comments as narrow deltas instead of stopping
   after the first findings and rebuilding the full PR-surface model.
3. The local audit came too late and was still incomplete.
4. Existing repository prior art was not compared before claiming readiness:
   `.github/scripts/iccdev-apple-simulator-smoke.sh` already showed the
   simulator fresh-launch pattern.
5. Existing sibling app behavior was not compared before claiming readiness:
   `examples/ios-benchapply/BenchApplyHost.mm` already removed stale persisted
   report output before writing a new report.
6. Suppressed review-body findings were treated as after-the-fact evidence
   instead of first-class review inputs.
7. A moving branch caused comments anchored to older commits to be confused
   with current-state findings. Timestamp and reviewed-commit checks were not
   applied consistently.
8. The agent relied on successful first-run validation as a proxy for
   repeatability. That did not prove fresh simulator launch behavior or stale
   report cleanup.

## Required Remediation

1. Treat any review that reports `Previously missed` unchanged-code findings as
   a failed convergence signal.
2. Do not request or rely on another cloud review after a second cycle finds a
   new blocker. Record `review-stop: FAIL - maintainer direction required`.
3. Before every PR-branch push after review feedback, run a review-repair gate
   that records the base SHA, head SHA, review IDs, unresolved threads,
   suppressed review-body findings, changed files, contract matrix, validation
   commands after the latest edit, and stop status.
4. Require the review-repair gate to fail closed when a review reports partial
   file coverage and the branch has not had a separate whole-PR local review.
5. For Apple helper/app changes, require a sibling/prior-art scan covering
   existing smoke helpers, existing iOS examples, CMake presets, generated
   Xcode settings, runtime artifact paths, and README command snippets.
6. Record review comments by reviewed commit and timestamp. Do not judge a
   finding against the current diff until confirming whether a later commit
   already fixed it.
7. Treat local `/review` and cloud PR review as final confirmation only, not as
   implementation discovery.

## Workarounds Until Automation Exists

1. Prefer manual maintainer review after a review-stop event. Do not start
   another automated review cycle unless the maintainer explicitly directs it.
2. Before pushing any repair, write a short local ledger with reviewed SHA,
   current SHA, changed files since review, affected contracts, and exact
   validation evidence.
3. Run targeted repeatability tests, not just first-success tests, for launch
   helpers and persisted artifacts.
4. Compare every new helper to existing repository helpers with the same role.
5. Compare every new example app to existing example apps with the same runtime
   artifact or device/simulator behavior.
6. For PR comments, include whether a finding was valid at the reviewed commit
   and whether it is already fixed at the current head.

## Decision

This PR exceeded the review-cycle stop threshold. The correct state after the
second new blocker was:

```text
review-stop: FAIL - maintainer direction required
reason: repeated cloud reviews found previously missed unchanged-code defects
after local review and after a claimed cumulative audit
```

Future upstream PR work must treat repeated review findings as a stop signal,
not as permission to continue serial patching. The agent must prove local
branch convergence before cloud review, or report that convergence cannot be
established.
