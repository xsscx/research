Why This Sample

The larger ICC profiles in this repo carry LUT payloads that turn the poster into a scrolling dump. This one is the opposite: nearly all bytes are scaffolding, which makes the conformance gaps visually obvious.

Structure Map

Read this top-down, not left-right. The poster follows the file: 128-byte header -> tag count -> one 12-byte tag entry -> one 13-byte body -> 3 bytes alignment pad.

Analyzer Notes Worth Preserving

  • H4 still treats cenc as an unknown device class, which is useful context when comparing ICC.1 and ICC.2 support.
  • H6 and H170 are the main structural alarms: the PCS is null instead of XYZ or Lab .
  • H8, H112, and CF-008 all converge on the same point: the illuminant is zero, not D50.
  • H13, H110, and CF-040 all report the missing desc, wtpt, and cprt tags.
  • H122 notices that rfnm is stored with a 13-byte body, even though the file-level layout is padded to a 4-byte boundary.
  • H127 and CF-097 both treat rfnm as an undocumented private tag.

Why This Looks More Like TIFF_LE

  • The main figure is a file-structure drawing, not just a decorative web page.
  • The callouts point to byte ranges and explain why each region exists.
  • The hex rows are subordinate to the structure map, the same way corkami posters treat the byte dump as evidence, not the whole story.
  • The right rail is split into provenance, interpretation, and quality findings instead of one long prose block.
