# UA -- User Agent Image & ICC Profile Fuzzer Harness

Browser-based security testing harness that exercises user agent image decoders
and ICC color profile parsers. Runs entirely client-side -- no server logic, no
dependencies beyond a static HTTP server.

<img width="3672" height="1917" alt="image" src="https://github.com/user-attachments/assets/8092db67-8705-4cef-8aef-f2a25afaa421" />

## Quick Start

```bash
# From the repository root
cd ua
python3 generate-manifest.py --root ..
cd ..
python3 -m http.server 8080
# Open http://localhost:8080/ua/ua-image-icc-fuzzer.html
```

## Architecture

### Three-Panel Layout

| Panel | Content |
|-------|---------|
| **Render** (left) | Live image display + ICC info overlay |
| **Log** (center) | Timestamped event stream (OK/WARN/ERR/CRASH) |
| **Findings** (right) | CWE-annotated security findings with severity |

### Components

| File | Purpose |
|------|---------|
| `ua-image-icc-fuzzer.html` | V2 fuzzer harness (single-file, ~700 LOC) |
| `manifest.json` | File inventory generated by `generate-manifest.py` |
| `generate-manifest.py` | Scans repo for image/ICC/XML files |

### Processing Pipeline

1. **Manifest load** -- `manifest.json` lists all testable files with type/ext metadata
2. **Filter/shuffle** -- Select by type (All/Images/ICC/XML) or format (PNG/JPEG/TIFF/etc)
3. **Batch processing** -- Configurable batch size (1-64) with adjustable delay
4. **Image path**: `<img>` load -> canvas decode (Display P3) -> pixel readback -> quality checks
5. **ICC path**: `fetch()` -> ArrayBuffer -> Web Worker pool (off-main-thread header parsing)
6. **Finding classification**: CWE mapping with severity (CRITICAL/HIGH/MEDIUM/LOW/INFO)

### ICC Worker Analysis (off-main-thread)

Web Workers parse ICC binary headers and perform:
- Header field validation (size, magic, version BCD, rendering intent)
- PCS illuminant D50 check (s15Fixed16 fixed-point comparison)
- Reserved bytes validation (bytes 100-127 must be zero)
- Profile ID extraction (bytes 84-99)
- Tag table walk with bounds checking
- **Duplicate signature detection** (CWE-694)
- **Tag overlap detection** -- partial overlaps flagged (CWE-119)
- **Tag alignment check** -- 4-byte alignment per ICC spec
- Memory stress via ArrayBuffer fragmentation (exercises GC)

### Image Quality Checks

- Flat/degenerate detection (all pixels same color)
- Fully transparent detection (all alpha = 0)
- Extreme dimension detection (>16384 in either axis)
- Zero-dimension detection (loaded without error)
- createImageBitmap alternate decode path exercise

### CWE Classification

All findings are classified with CWE codes and severity levels:

| CWE | Severity | Pattern |
|-----|----------|---------|
| CWE-119 | CRITICAL | Buffer error, tag overlap |
| CWE-122 | CRITICAL | Heap buffer overflow (tag overflows) |
| CWE-131 | HIGH | Size mismatch |
| CWE-345 | CRITICAL | Invalid magic number |
| CWE-400 | HIGH | Resource exhaustion (timeout, extreme dims) |
| CWE-682 | MEDIUM | PCS illuminant deviation |
| CWE-789 | HIGH | Suspicious tag count |
| CWE-843 | CRITICAL | ICC decoded as image (type confusion) |

## Manifest Generation

```bash
# Default scan (test-profiles, fuzz, mangled-images, iccDEV/Testing, source-of-truth)
python3 generate-manifest.py --root ..

# Full scan (includes CFL/AFL corpus directories)
python3 generate-manifest.py --root .. --full

# Stats only (no file write)
python3 generate-manifest.py --root .. --stats
```

The manifest classifies files by extension and ICC magic bytes (`acsp` at offset 36).
Output: `manifest.json` with `{total, stats, files[{path, type, ext}]}`.

## Export Formats

- **JSON**: Full findings with path, detail, severity, CWE, timestamp
- **CSV**: Tabular format for spreadsheet analysis

## Requirements

- Modern browser (Chrome 90+, Firefox 90+, Safari 15+)
- Local HTTP server (CORS requires same-origin for fetch)
- Repository checked out (manifest paths are relative)

## Security Note

This harness processes **intentionally malicious** files. All processing happens
client-side in the browser sandbox. The Web Worker pool isolates ICC parsing from
the main thread. Findings indicate potential browser decoder vulnerabilities.
