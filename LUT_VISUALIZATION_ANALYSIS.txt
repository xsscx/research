## 1. What Does LUT Visualization Do?

The LUT visualization module provides:

1. **SVG Output**: Generates scalable vector graphics (.svg files) visualizing 1D curves and nD LUT structures
2. **TIFF Export**: Exports multi-dimensional CLUT (Color Lookup Table) data as TIFF images
3. **Curve Analysis**: Handles TRC (Tone Reproduction Curve) tags for RGB, Gray channels
4. **Multi-dimensional LUT Processing**: Processes AToB/BToA, Preview, Gamut, and Lut8/Lut16 tags
5. **Sandboxed Execution**: Runs visualization in isolated child process with resource limits
6. **Safety Mechanisms**: OOM guards, integer overflow checks, signal recovery, path validation

### TIFF Writing
bool WriteTIFF(const char *name, float dpi, int color_model, uint8_t *buffer,
               size_t width, size_t height, int channels, int depth)
  Line: 919-1137
  Purpose: Write uncompressed TIFF file with IFD and pixel data
  Parameters:
    - name: output filename
    - dpi: resolution (100 default, validated against overflow)
    - color_model: TIFF_MODE_* (RGB, CMYK, CIELAB, GRAY)
    - buffer: pixel data (8/16/32/64-bit)
    - width/height: image dimensions
    - channels: samples per pixel
    - depth: bits per sample (8, 16, 32, 64)
  File Structure:
    1. Header: "II" or "MM" (endianness) + 42 + offset to IFD (8)
    2. IFD (Image File Directory): 15 tags
       - TIFF_WIDTH, TIFF_HEIGHT (required)
       - TIFF_BITSPERSAMPLE (channels as SHORT array or single LONG)
       - TIFF_COMPRESSION = NONE
       - TIFF_INTERPRETATION = color_model
       - TIFF_STRIPOFFSETS, TIFF_STRIPBYTECOUNTS
       - TIFF_SAMPLESPERPIXEL, TIFF_ROWSPERSTRIP
       - TIFF_XRESOLUTION, TIFF_YRESOLUTION (as RATIO: numerator/1000)
       - TIFF_PLANARCONFIG = 1 (interleaved)
       - TIFF_RESOLUTIONUNIT = 2 (inches)
       - TIFF_PREDICTOR = 1 (none)
       - TIFF_SAMPLE_FORMAT (UINT/FLOAT based on depth)
    3. Padding: alignment to 4-byte boundary
    4. Bits per sample array (if channels > 1): SHORT[channels]
    5. Resolution ratio pairs: (numerator, denominator)
    6. Strip offset/byte count placeholders
    7. Pixel data (uncompressed)
    8. Backfill: strip offset and byte count
  Special Handling:
    - CIELAB data: shift a*,b* from unsigned [0,256] to signed [-127,127]
    - Overflow checks: SafeMul3/4 for all size calculations
  Supported Depths: 8, 16, 32, 64 bits per sample

## 6. processLuts() Complete Work Flow

1. Determine output basename (remove .icc/.icm extension)
2. Validate output paths (Linux/Unix only)
3. Create and open SVG file
   SVGOut svgfile(svgPath)
   svgfile.WriteHeader(point2D(0,0), point2D(8*25.4, 8*25.4))
   // 8 inches × 8 inches = 203.2mm × 203.2mm
4. Iterate through all profile tags (pIcc->m_Tags)
   
   For 1D TRC Tags (Red, Green, Blue, Gray):
     Call output1DLUT() → SVG rendering
   
   For nD LUT Tags (AToB0-3, BToA0-3, Gamut, Preview0-2):
     a. Extract CIccMBB (Lut8/16/AtoB/BtoA)
     b. Process input curves (curveA) → output1DLUT() for SVG
     c. Process output curves (curveB) → output1DLUT() for SVG
     d. Process matrix curves (curveM) → output1DLUT() for SVG
     e. Process CLUT (nD data):
        - clut->Begin() [initialize grid info]
        - Get grid dimensions (GridPoints, GridPoint(1/2))
        - Calculate tiling for square-ish grid
        - Allocate image buffer with overflow checks
        - Copy CLUT data to image buffer with proper indexing
        - Write TIFF file

5. Close SVG file

## 8. Output Formats

### SVG Output Format

File Structure:
<?xml version="1.0" encoding="utf-8"?>
<svg version="1.1" id="Layer_1" 
     xmlns="http://www.w3.org/2000/svg"
     xmlns:xlink="http://www.w3.org/1999/xlink"
     x="0" y="0" 
     viewBox="0 0 567.73 567.73"
     style="enable-background:new 0 0 567.73 567.73;"
     xml:space="preserve">
  
  <g id="group_name">
    <!-- Text, lines, polylines, etc. -->
  </g>
  
  <!-- More groups -->
  
</svg>

Coordinate System:
- Units: Millimeters (mm) for geometry, Points (pt) for text/viewBox
- Conversion: mm2point = 2.834645669 (72 pt/inch ÷ 25.4 mm/inch)
- SVG Viewport: 8" × 8" = 203.2mm × 203.2mm = 567.73pt × 567.73pt
- viewBox: "0 0 567.73 567.73" (in points)

1D Curve Layout:
- Title: "TagName   [description]" at (8*0.5*25.4, 0.25*25.4) mm
- Y axis range: 0.5"→7.5" (7.0" = 177.8mm)
- X axis range: 0.5"→7.5" (7.0" = 177.8mm)
- Sampling: min(1000, curve_size) points
- Rendering: <polyline> unfilled, black stroked

Elements Used:
- <g> groups with id containing curve name (XML-escaped)
- <text> for titles, axis labels (font-family="Arial", font-size=14pt)
- <line> for axes and tick marks (stroke-width=0.5pt, black)
- <polyline> for curve traces (unfilled, black stroke)

XML Security:
// Characters escaped to prevent XSS (CWE-79)
& → &amp;
< → &lt;
> → &gt;
" → &quot;
' → &#39;

### TIFF Output Format

File Structure:
Offset  Size  Content
0       2     Byte order (II=little-endian, MM=big-endian)
2       2     Magic number (42)
4       4     Offset to first IFD (8)
8       2     IFD entry count (15)
10      180   IFD entries (12 bytes each)
...     var   Pixel data (uncompressed, interleaved samples)

IFD Tags (15 entries):
TIFF_WIDTH, TIFF_HEIGHT
TIFF_BITSPERSAMPLE
TIFF_COMPRESSION = NONE
TIFF_INTERPRETATION = color_model
TIFF_STRIPOFFSETS, TIFF_STRIPBYTECOUNTS
TIFF_SAMPLESPERPIXEL, TIFF_ROWSPERSTRIP
TIFF_XRESOLUTION, TIFF_YRESOLUTION
TIFF_PLANARCONFIG = 1 (interleaved)
TIFF_RESOLUTIONUNIT = 2 (inches)
TIFF_PREDICTOR = 1 (none)
TIFF_SAMPLE_FORMAT (UINT/FLOAT based on depth)

Color Model Mappings:
RGB/CMY/XYZ/Luv/YCbCr/Yxy/HSV/HLS → TIFF_MODE_RGB (2)
CMYK → TIFF_MODE_CMYK (5)
Lab → TIFF_MODE_CIELAB (8)
Gray/Gamut/default → TIFF_MODE_GRAY_BLACKZERO (1)

Bit Depth Support:
- 8-bit: uint8_t, quantized [0.0, 1.0] → [0, 255]
- 16-bit: uint16_t, quantized [0.0, 1.0] → [0, 65535]
- 32-bit: float (IEEE 754), raw
- 64-bit: double (IEEE 754), raw

Resolution:
Default: 100 DPI
Encoded as: (dpi * 1000) / 1000 in RATIO format
Example: 100 DPI → XResolution = 100000/1000
